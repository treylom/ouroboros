# SearchFlow

**소스 등급 가중 점수 + 은닉 문턱 게이트로 깊이를 사후 결정하는 리서치 공정.**

깊이를 사용자에게 미리 묻지 않는다. 쉬운 질의는 1라운드에서 문턱을 넘어 즉시 끝나고, 어려운 질의만 재조사를 돈다 — 평균은 내려가고 하한은 올라간다.

## 0. 두 층

- **core (기본)**: 순정 Claude Code 또는 순정 Codex CLI + 이 스킬 번들만으로 완주한다. 외부 패키지 · 내부 MCP · 특정 플러그인 requirement **0**. node 실행기는 `scripts/preflight.sh`(§5.1) 가 확보한다. 없으면 관리자 권한 없이 내려받고, 그래도 못 받으면 `degraded=no-node-runtime` 라벨을 남기고 완주한다.
- **enhanced (선택)**: 환경에 있으면 얹는다. 없으면 **에러 없이 core 로 강등하고 격하 라벨을 보고서에 남긴다** — 조용한 skip 금지.

`scripts/preflight.sh`(§5.1) 다음에 `scripts/env-detect.mjs` 를 1회 실행해 참고값을 얻는다(인자 없이 호출 = exit 0 고정, stdout 1줄 JSON) — 호출은 preflight JSON 의 `node` 경로로. **탐지 결과는 리드만 소비한다.**

> ⚠️ `multi_agent_api` 값은 참고다. **multi-agent 경로의 최종 판정은 리드가 자기 tool 목록을 보고 한다** — shell 스크립트가 모델의 tool 노출을 대신 판정하면 틀린다.

### 0-1. 공정 소유권 — 스킬이 쥐나, 서버가 쥐나

위 두 층과 **직교하는 축**이다(core/enhanced = 어떤 도구를 얹나 · 아래 = 누가 공정을 강제하나).

| 모드 | 조건 | 채점 기준이 사는 곳 | 판정 |
|---|---|---|---|
| **skill-owned (기본)** | `searchflow_*` 도구가 tool surface 에 **없다** | `references/scoring.md` — 독립 채점자가 읽고 채점 | 독립 채점자 |
| **server-owned** | `searchflow_start`·`searchflow_submit`·`searchflow_gate` 가 tool surface 에 **있다** | MCP 서버 내부(파일로 존재하지 않음) | 서버 |

- **판정 주체 = 리드가 자기 tool 목록을 보고 한다.** 위 `multi_agent_api` 주의와 같은 이유로 shell 이 대신 판정하지 않는다. 서버가 안 떠 있으면 도구가 애초에 안 보이므로 **탐지 실패 = skill-owned 로 fail-open**(에러 ❌).
- server-owned 면 리드는 **`scoring.md` 를 열지 않는다.** 독립 채점자는 등급 기준을 위해 읽는다. 프레임·브리핑·판정을 전부 서버에서 받고, 서버가 준 `worker_brief` 를 **그대로** 워커에게 넘긴다(문장을 늘리지 않는다 — §P2.5 와 같은 이유).
- 어느 쪽이든 **보고서에 모드를 적는다**: `process_owner: skill | server`. 조용한 전환 금지 — 같은 질의가 다른 깊이로 끝났을 때 원인이 모드였는지 알 수 있어야 한다.

> ⚠️ 이 표는 **2026-08-02 신설**이다. 그전까지 서버는 존재했지만 스킬이 그 존재를 몰랐다 — 즉 「2모드」가 설계 문서에만 있고 실행 경로엔 없었다. 두 모드를 비교하려면 먼저 모드가 있어야 한다.

## 0.5 P-1 — 모호도 게이트 (P0 앞 · 2026-09-01 신설)

**깊이는 안 묻는다 — 이 게이트가 고치는 것은 «질문 자체»다.** 검색 «후» 품질 루프(P4)와 직교한다.

조사에 들어가기 전에 질의를 **4항목**으로 채점한다. 각 항목 = **O/X + 근거 1줄**(LLM 채점 · temp 0.2):

| 항목 | 무엇 |
|---|---|
| **① 할 일** | 목표 동사가 있는가 |
| **② 대상 범위 한정** | 무엇까지가 조사 대상인지 한정어가 있는가 |
| **③ 완료 판정 기준** | 「무엇을 하면 끝인가」가 유계인가 — 아래 유계성 규칙 |
| **④ 제약** | (a) 크기[시한·형식·분량]·(b) 정답분기[기준일·관할·버전 등] — O/X 판정은 (b) 기준 단독 |

**채점 규칙**:

- **③완료기준 유계성(K1)**: ③ = O iff 「①할 일 + ②범위 + ④(a) 크기 제약 «문면»이 합쳐져 '무엇을 하면 끝인가'와 '답의 최대 크기'가 함께 유계」. 별도 수락시험·산출형식은 요구하지 않는다. 「여러/몇 개」류 anchor 없는 맨 수량어(「여러 대안」·「사례가 많다」)가 답 크기를 무계로 만들면 X.
- **ⓐ' 「등」 세칙 v2**: 「등」이 붙은 예시 열거를 무계로 세지 않는 조건 = ⑴ **닫힌 카테고리**(발주자 환경 안에서 열거 가능한 유한 집합 — 예: 「영업팀·개발팀·디자인팀 등」 = 우리 회사 부서·「hook 설정 등」 = 우리 하네스 기능) 또는 ⑵ **열린 카테고리 + 대표 표본 독해 성립**(「전수/모든/빠짐없이」류 지시가 없고 명시 예시가 anchor — 예: 「memorybank나 graphify등」). **⑵ 효력 한정**: 「등」을 «무계 신호로 세지 않는다»까지만 — 최종 유계 판정은 ③ K1(목표·무게중심 포함) 몫, ⑵ 단독으로 ③ 선점 ❌(목표 부재 열린 카테고리는 ⑵ 를 지나도 ③ 에서 X). 무계 유지(③ X 방향) = 열린 카테고리 + 「전수」류 지시 · anchor 없는 맨 수량어.
- **④' 제약 2종 분리 + 판정 순서(상호 참조 0)**: **step 1** — 문면의 제약 후보에 역할 태그(배타 파티션 ❌·한 제약이 두 역할 겸행 가능): **(a) 크기 제약**(시한·형식·분량 — 독립 감점 ❌·③ 유계 판정의 입력으로만) / **(b) 정답분기 제약**(기준일·관할·대상 버전·안전 조건 등 — 답 «크기»는 안 바꾸나 «어느 답이 맞는지»를 바꾸는 파라미터). ④ 의 O/X = **(b) 기준 단독**: 과제 성격상 정답분기 파라미터가 필요한데 문면에 없으면 **X — 면제 불가**. 판별선 = **암묵 현재/불요**(발주 시점 «지금» 상태 조사 — ④(b) 불요 = O) vs **명시 필요**(기준시점·관할·버전이 정답을 가르는 과제 — 부재 = X). **step 2** — ③ 유계 판정은 ① + ② + ④(a) «문면»만 입력(④ 판정 결과 참조 ❌).
- **㉮ 지시대명사 세칙**: 문면 안에서 선행 지시 대상이 해소되지 않는 지시대명사(「이거·그거·이들」) = **② X 고정** — 수신자가 발주자 머릿속 컨텍스트를 공유한다고 가정하지 않는다(추론 해소 ❌).
- **원래 말 기준(사람이 시킨 조사 · 0.55.12)**: 채점 대상은 **사람이 처음 한 말 그대로**다(`gate.original_question` — 봇이 다시 쓴 긴 지시문 ❌). 첫 채점(`initial_verdicts`)은 그 원래 말을 채점한다. 봇이 사람 말을 지시문으로 다시 쓴 뒤 그 지시문을 자기가 채점하면 늘 «명확»이 나와 사람에게 한 번도 묻지 않게 된다(실사용 89건 중 첫 채점 X 0건이었던 원인). 질문(`question`)이 원래 말과 다르면 운영자 인터뷰가 필수다 — 인터뷰 없이 바로 P0 로 가는 길은 `question` = 원래 말 하나뿐이다.
- **내부 미지 구분**: 조사로 밝힐 대상의 «내부 미지»(예: 어느 요금제가 있는지)는 게이트 트리거가 아니다 — 발주가 그 미지를 조사 과제로 지정했으면 O.
- **점수 방향**: 노출 점수 = O개수/4 (이산: 0·0.25·0.5·0.75·1.0) = **명확도**(높을수록 명확). **통과 조건 = 「4항목 전부 O」** — 소수 문턱을 이산 축에 표기하지 않는다(채점자가 없는 중간값을 만든다).

**발동 (하나라도 X)**:

4항목 채점은 인터뷰를 열지 정하는 가벼운 1차 판정이다. 전부 O 면 바로 P0, 하나라도 X 면 **우로보로스 인터뷰**로 운영자와 질문을 좁힌다 — 봇이 혼자 다듬지 않는다.

1. **조사 시작 ❌.** X 채점을 `searchflow_start` 에 내면 게이트 발동 응답에 `<<<INTERVIEW_INITIAL_CONTEXT` 와 `INTERVIEW_INITIAL_CONTEXT>>>` 사이로 **서버가 조립한 `initial_context` 완성 글**이 실린다. `ouroboros_interview` 를 그 글 그대로(한 글자도 요약·번역·줄임 ❌) 시작한다 — 완성 글의 꼴은 첫 줄 `원질문: <원질문의 JSON 문자열>`(원질문을 JSON 문자열로 바꾼 결과 — 따옴표·역슬래시·줄바꿈·탭 등 제어 문자가 이스케이프되어 한 줄이 된다 · 한글 등 보통 글자는 그대로) + 빈 줄 + **검색 인터뷰 지시문 전문**(서버 `INTERVIEW_FRAME`). 지시문의 요지: 인터뷰는 «무엇을 찾을지»만 좁힌다 — 물을 칸은 ① 찾을 것 ② 범위 ③ 검색 끝 기준 ④ 기준일(언제 기준의 사실인가) ⑤ 마감 시한(원질문에 시한이 없으면 다른 빈 칸과 같은 메시지에서) 다섯뿐이고, 조사 결과를 어디에 어떻게 쓸지(길이·게시처·화면 구성·디자인)는 묻지 않는다. 빈 칸은 한 메시지에 묶어 한 번에 묻고, 칸마다 보기 2~3개를 붙인다. 맨 처음에는 자동 모드 칸 한 줄(«[자동 모드 칸] 자동 모드로 할까요? 예/아니오 — ‘예’면 남은 칸은 제가 알아서 채워 조사합니다.»)만 따로 묻고, 운영자가 «예»라고 답하면 남은 칸은 봇이 채운다(봇이 채운 답 머리 `[from-auto]` · 아래 «자동 모드»). 다섯 칸이 다 차면 새 칸을 열지 않고, 요약 확인 질문 하나만 한다(인터뷰가 끝나려면 통과 회차가 한 번 더 필요하다).
2. **인터뷰가 낸 질문은 하나도 빠짐없이 운영자에게 그대로 전달한다**(창구 = §4 「운영자 질문 창구」 사다리). 봇이 코드·조사로 대신 답하는 경로는 쓰지 않는다(예외 = 아래 «자동 모드»뿐). 보내기 «전»에 `searchflow_await_operator` 로 기다림을 기록한다 — 서버가 이때 인터뷰 시작 문맥을 검사해서, 완성 글과 다르면 «보내지 마라»로 거부하고 완성 글을 다시 준다(그 인터뷰는 버리고 새로 연다 · 운영자 왕복을 끝에서 버리지 않게). 기록이 되면 질문을 보내고 턴을 끝낸다. 대기 시간 상한 없음.
3. **답이 오면** `searchflow_pending` 으로 어느 인터뷰·어느 질문의 답인지 찾아 `ouroboros_interview`(session_id · answer · last_question)에 넣는다 → 다음 질문 → 2 반복.
   - **같은 확인 재질문 ❌**: 운영자가 «이대로 맞나요?» 확인에 «네» 한 낱말로 답했으면 확인을 다시 묻지 않는다 — 인터뷰가 «안정 회차 한 번 더»를 요구하면 운영자 대신 `ouroboros_interview` 에 answer `done` 을 넣는다(인터뷰 도구의 done 신호 = 저장된 모호도가 통과선 아래일 때 안정 회차 +1 · 통과선 위면 인터뷰가 새 질문을 낸다 — 그 새 질문은 운영자에게 묻는다). 자정을 넘겨 «오늘»의 날짜가 바뀐 것뿐이면 다시 묻지 말고 기준일을 조사 시작 날짜로 정해 `gate.evidence` 에 적고 정정은 `answer_summary` 에 한 줄. 질문 글에 «오늘»을 날짜로 적을 때는 대화 맥락의 날짜가 아니라 지금 시계(`searchflow_await_operator` 응답의 `today_local`)를 쓴다. server-owned 면 `searchflow_await_operator` 가 직전 사람 답이 맨 «네»일 때만 «또 확인 질문»과 «답 받은 질문과 날짜만 다른 질문»을 기록 거부한다(대기 기록 0). 직전 답이 맨 «네»가 아니면(«네, 범위는 국내만»·«아니요 날짜가 틀렸어요»·«네? 틀렸는데요») 무엇도 막지 않고, 맨 «네» 뒤라도 확인 문형이 아닌 새 칸 질문은 막지 않는다. 확인 문형 = «이대로 맞나요/괜찮/진행/좋/할까»·«맞나요?»·«맞습니까»·«맞을까요»·«맞는지 확인» — 목록 밖 재확인(«진행해도 될까요?»·«Is this right?»)은 샌다(넓히면 새 칸 질문까지 잘못 막혀서 좁게 둠 · 대가 = 운영자 질문 1회). 대가: «네» 뒤 봇이 스스로 실수를 발견해 다시 확인하고 싶은 경우도 막힌다 — 그때는 바뀐 내용을 담은 새 칸 질문(확인 문형이 아닌)으로 묻는다. 근거 = 실제 사용 세션의 원장 사례: 3회차 확인 질문은 23:58 에 «오늘(2026-11-07)»로 기록(그때는 맞음) → 운영자가 자정 뒤 00:07 «네» → 봇이 날짜만 바로잡은 4회차 확인을 다시 보냄.
4. **인터뷰 완료**(모호도 ≤ 0.2 + 항목 하한 + 연속 2회 — 인터뷰 도구가 판정)면 **종료 감사**: 다듬어진 질문을 4항목으로 다시 채점한다. 전부 O 가 아니면 인터뷰로 돌아간다. 다듬어진 질문은 인터뷰 기록(질문·답)에서 가져온다 — 봇이 새로 의역하지 않는다.
5. **마감 시한 = 인터뷰 ⑤ 칸** — 원래 말에 시한이 없으면 인터뷰가 다른 빈 칸과 같은 메시지에서 묻는다(따로 왕복하지 않는다 · 이미 답을 받았으면 다시 묻지 않는다). 받은 시한은 `deadline_source = operator` 로 낸다.

**사람이 시킨 조사 · 원래 말 · 마감 시한 · 자동 모드 (0.55.12 · 0.55.13 보수판)**:

서버는 사람 글(원래 말 · 질문 · 시한 인용 · 인터뷰 시작 글과 운영자 답)을 유니코드 NFC 로 맞춘 뒤 본다 — 자모가 분리된(NFD) 글도 같은 글로 본다(0.55.13).

- **누가 시켰나** = `gate.origin`. 생략하면 `human`(사람이 시킨 조사). 사람이 시키지 않은 봇 자체 조사(정기 점검·스스로 연 조사)만 `origin = bot` + `origin_reason`(사람이 시키지 않은 이유 1줄)로 아래 두 의무에서 빠진다. 근거가 비었거나 여러 줄이면(줄을 나누는 글자 전부 — 줄바꿈·세로 탭·폼 피드·U+2028 등) 거부.
- **원래 말 필수**: 사람이 시킨 조사는 `gate.original_question` 에 사람이 처음 한 말을 글자 그대로 넣는다. 없으면 거부. 원래 말에 지시대명사(이거·그거·이걸·이들 등)가 있는데 첫 채점 ② 가 O 면 거부하고 원래 말로 인터뷰를 열게 한다(㉮ — 서버가 원래 말에서 직접 본다 · 낱말 가운데의 «…이거나…» 같은 꼴은 세지 않는다 · 선행 대상이 문면 안에 있는지는 서버가 못 가려 지시대명사가 한 번이라도 있으면 거부한다(«이건희» 같은 이름도 걸린다) — 비용은 운영자 질문 1회). 서버가 못 잡는 꼴: «그 제품»·«이 건» 같은 관형 지시어 + 명사, 붙여 쓴 «근데그거», «해당 건»·«위 내용» — 이런 원래 말은 첫 채점에서 봇이 ② 를 X 로 매긴다(규칙 ㉮ 그대로 · 서버 검사는 지시대명사 낱말만).
- **마감 시한**: 사람이 시킨 조사에서 사람이 시한을 안 정했으면(`deadline_source = default` 또는 생략) 기본값으로 넘기지 않는다 — 거부 응답이 인터뷰 시작 글을 함께 주니, 그 인터뷰의 ⑤ 칸으로 (다른 빈 칸과 함께) 묻고 `deadline_source = operator` 로 다시 낸다. 인터뷰 없이 `operator` 로 내려면 원래 말 속 시한 구절을 `deadline_quote` 에 글자 그대로 넣는다(0.55.13 꼴 검사 + 문맥 검사). 받는 꼴 = 40자 이하이고 인용 «전체»가 다음 중 하나, 또는 «날짜/날 + 때·시각» 순서로 이은 것(«11월 10일 오후 6시까지»·«11/10 18:00까지»·«오후 3시 30분까지»·요일 괄호 «11월 - **자동 모드**(2026-11-06 운영자 지시 · 0.55.13 자동 모드 칸): 인터뷰는 맨 처음 자동 모드 칸 한 줄(«[자동 모드 칸] 자동 모드로 할까요? 예/아니오 — ‘예’면 남은 칸은 제가 알아서 채워 조사합니다.» — 서버 `AUTO_SLOT_LINE`)만 따로 묻는다. 운영자가 «예»라고 답하면 남은 인터뷰 질문은 봇이 스스로 답을 채워 인터뷰 모호도가 통과선(≤ 0.2) 아래로 내려갈 때까지 이어 가고(인터뷰 완료 검사는 그대로), 시한은 기본값을 써도 되고 시한 인용(`deadline_quote`)도 요구하지 않는다(보고서 `deadline=default` 표기). 근거는 그 칸의 답뿐이다 — 원래 말·봇이 쓴 `question` 의 «자동 모드로 해 줘»·«자동 모드로 안 묻고 유니코드 NFC, 전각 영문·기호, 폭 없는 글자 6개(U+200B·200C·200D·2060·FEFF·00AD) 차이만 무시) 회차 가운데 답이 있는 마지막 회차의 답이 «예» 한 낱말(«예»·«네»·«넵»·«응»·«yes»·«y» · 끝의 «.»·«!»·«~»·«。»는 허용 · 사람 답 머리 `[from-user]` 는 맨 앞 하나만 떼고 본다)이고, **사람이 답한 회차가 그 칸 «예» 하나뿐**이고, 원래 말이 시한(«마감·시한·납기»·«내일까지»·«by Friday» 같은 시한 꼴)을 말하지 않고 시한 표지 낱말(«까지»·«안에»·«안으로»·«내에»·«내로»·«이내»·«전에»·«중으로»·«연내»·«늦어도»·«by»·«until»·«till»·«before»·«within»·«prior [자동 모드 칸] …»·칸 뒤에 다른 질문) · «아니오»·«자동 모드로»·«예, 범위는 국내만»·«네 맞아요» 같은 답 · 칸 답 머리가 봇 표지이거나 `[from-user]` 하나 말고 다른 머리(`[from-user][refined] 예`·`[from-code] 예`·`[from-user] [from-user] 예`) · 칸 «예» 말고 사람 답 회차(«범위는 국내만요»·운영자가 직접 한 «네 맞아요.» 확인·칸 앞 답) · 원래 말의 시한·표지 낱말·시간 낱말 — 이때 봇은 남은 칸을 운영자에게 묻는다. **호스트 의무**: 자동 모드로 봇이 스스로 채운 인터뷰 답(끝의 «이대로 맞나요?» 확인 답 포함)은 머리에 `[from-auto]` 를 붙여 기록한다 — 머리표 없이 채우면 운영자 답 회차로 보여 자동 모드가 꺼진다. 한계(서버가 뜻을 못 봄): 인터뷰가 칸 줄을 바꿔 물으면 꺼진다(질문 1회 비용) · 원래 말에 시간 낱말·표지 낱말이 하나도 없는 시한(«급해요»·«발표 전 자료로»·«출장 가기 전 정리» — «회의 들어가기 전에»는 «전에»로 잡힘)은 못 본다 · 목록 낱말이라도 다른 꼴은 못 본다(영문 굴절·붙임표 «next weeks»·«todays»·«this-week»·«thisweek», 줄임 «Weds»·«금욜», 앞에 숫자·영문이 붙은 «2026Q3», 한글 숫자 «시월 중»·«세 시», 줄임·옛말 «담주»·«낼»·«내달»·«익일», 낱말 사이 빈칸 «이 번 주», 목록 밖 «noon»·«EOY»·«3Q»·«this morning», 폭 없는 글자 6개 밖의 보이지 않는 글자를 끼운 낱말) · 호출자가 넘긴 선호가 `[from-auto][user_preference]` 머리로 기록되면(우로보로스 자동 답) 그 안의 시한은 봇 회차라 보지 않는다 · 호출자가 사람 답에 봇 표지(`[from-auto]`·`[from-safe-default]`)를 거짓으로 붙이거나 인터뷰 기록을 거짓으로 쓰면 서버가 가리지 못한다(호출자 신고값). 원장 `p1_gate` 에 `auto_mode` · `auto_basis`(`interview`)가 남는다. 업그레이드 주의: 인터뷰 지시문이 바뀌었으므로 0.55.12 지시문으로 연 진행 중 인터뷰는 시작 글 검사에 걸린다 — 새 시작 글로 다시 연다.

- 최소 비용 = 운영자 답 2회(인터뷰 도구 기준 — 연속 2회 통과해야 끝나고, 답 없는 회차는 통과 불가 · 서버는 답 1회 이상만 확인). 명확한 질문은 1에 들어가지 않으므로 0회.
- **인터뷰 도구 실패**: 재개 최대 2회 → 그래도 실패 = 조사 ❌ + 운영자에게 「인터뷰 도구 실패 — 질문을 좁혀 다시 주시면 진행합니다」 1줄. 셀프 인터뷰로 대신하지 않는다.

**기록**: 시드 문서 표준 — 원질문 → 다듬어진 질문 · 첫 채점(`initial_verdicts`)과 마지막 채점 · 운영자 인터뷰(`operator_clarification` · 인터뷰 모호도 · 답한 회차 수) · 결정 이력. server-owned 면 세션 원장의 `p1_gate` 이벤트가 이 기록이다 — 운영자에게 물었는지·언제·몇 회차 답했는지를 원장에서 볼 수 있다. 세션 원장의 모든 줄에는 그 줄을 적은 시각 `at`(UTC ISO)이 붙는다 — 사건마다 «언제»를 원장에서 잰다(옛 판 원장 줄엔 없음).

**server-owned 강제**: `searchflow_start` 는 `gate` 인자(4항목 verdicts + evidence) 없이는 **P0 로 넘어가지 않는다**. 첫 채점(`initial_verdicts`)에 X 가 있었거나, 원질문(`original_question`)이 함께 들어왔고 질문과 다르면 `gate.operator_clarification`(interview_session_id · asked_via · asked_at · answered_at · answer_summary)이 필요하고, 서버가 그 인터뷰의 상태 파일을 직접 읽어 확인한다: 완료 상태 · 모호도 ≤ 0.2 · 비어 있지 않은 답이 있는 회차 1개 이상 · 인터뷰 시작 문맥의 첫 줄이(앞 공백·줄 끝 공백은 무시) 정확히 `원질문: <원질문의 JSON 문자열>` 임 · 둘째 줄부터가 검색 인터뷰 지시문(`[검색 인터뷰 지시]` 로 시작하는 글) «전문»과 같음 — 공백·줄바꿈의 개수 차이만 무시하고, 낱말이 하나라도 다르거나 다른 글이 섞이면 받지 않는다(지시문 없이 시작한 인터뷰, 표지 한 줄만 붙인 인터뷰, 원질문 칸 안에 표지 글자를 넣은 인터뷰 모두 거부). 하나라도 아니면 거부한다. 0.55.12 부터 그 앞에서 함께 본다: `gate.origin`(생략 = human) · 사람이 시킨 조사의 `original_question` 필수 · 원래 말 지시대명사 + 첫 채점 ② O = 거부 · 사람이 시킨 조사의 시한 기본값 = 거부(자동 모드 근거가 있을 때만 허용) · 인터뷰 없는 시한 `operator` = 원래 말 속 구절 인용(`deadline_quote`) 필수 · `origin = bot` 은 `origin_reason` 1줄 필수 — 원장 `p1_gate` 에 `origin` · `origin_reason` · `auto_mode` · `auto_basis` 가 남는다. 한계: 첫 채점과 원질문은 호출자가 신고하는 값이고, `origin` 과 `deadline_source = operator` 도 호출자 신고다(서버는 원래 말이 정말 사람 글인지, 시한을 정말 사람이 정했는지 증명하지 못한다 — 막는 것은 «원래 말을 빼고 다시 쓴 지시문만 내는» 실사용 꼴과 «시한을 말없이 기본값으로 넘기는» 꼴이다), 인터뷰 기록의 «누가 답했나»도 호출자가 붙인다 — 서버는 «사람이 답했다»를 증명하지 못한다. 첫 채점(`initial_verdicts`)은 언제나 필수이고(빠지면 거부 — 처음부터 명확했으면 verdicts 와 같은 값), 질문을 다듬었으면 원질문도 반드시 함께 보낸다. `self_interview_rounds` 는 0 만 받는다. SKILL 서사를 건너뛴 MCP 도구 직행도 같은 게이트를 밟는다. skill-owned 면 본 절 자체가 게이트다: P0 의 어떤 단계도 이 채점 전에 시작하지 않는다.

## 1. 공정 (P-1 → P0 → P4)

```
P-1 게이트  ── 질의 4항목 채점(전부 O = 진입) → 미달 = 조사 ❌ · 우로보로스 인터뷰 질문을 운영자에게 전달(§4) → 인터뷰 완료 → 재채점
P0 스코핑 ── 유형 판정 → 프레임 확정 → 깊이 라우팅 → 묶음 질문 1회(마감 시한 포함) → 권한 preflight
P1 스폰   ── 프레임 축마다 조사 단위 1개 (하네스별 분기 §3)
P2 수집   ── 워커: 근거 + SELF-REPORT(Y/N + 근거 1줄)만 반환. 등급 부여 ❌
P3 채점   ── 새 독립 채점자: 소스 등급·원문 대조 → 판정 파일 → 리드가 그대로 전달
P4 게이트 ── 문턱 통과 → 종료 / 미달 → 최저 축만 재조사(P1 로) → 최대 4라운드(재조사 3회)
```

### P0 — 스코핑

1. **유형 판정** — `references/frames.md` §1 판정표. 복합 허용, 실패 시 `discovery` 폴백.
2. **프레임 확정** — 같은 파일 §2 표에서 축 목록을 가져오고, 복합이면 §1 결합 규칙으로 접는다. 축 id = `f1`…`fN`.
3. **깊이 자동 라우팅** — 아래 §2 표. 사용자에게 깊이를 고르게 하지 않는다.
4. **묶음 질문 1회** — §4.
5. **권한 preflight** — §5.
6. **run_id 발급** — `sf-<YYYYMMDDTHHMMSSZ>-<4hex>`, 이후 모든 원장 라인·relay envelope 에 동일 값.

### P1 — 취득 (사다리 + 차단 게이트)

`references/acquisition.md` 의 사다리를 위에서부터, 같은 단 안에서는 최신 발행분부터(§1). **취득 시도 전에 차단 여부를 기계로 판정한다**:

```bash
node scripts/robots-gate.mjs <대상 URL> [...]
# exit 0=전건 allowed · 1=1건 이상 blocked(**정상 결과다 — 재시도·우회 신호 아님**) · 2=스크립트 오류
# blocked 면 stdout 의 `ledger` 를 그대로 sources.jsonl 에 넣는다(grade=UNREACHABLE·status=unreachable)
```

- 판정은 **적용 가능한 User-agent 그룹 중 가장 엄한 것**이다. `*` 만 보면 안 된다 — 발행처가 `*` 는 열어두고 **AI 엔진 계열 이름에만 전면 불허**를 거는 경우가 실재한다(`fixtures/blocked-observed.md` 실측). `--ua-only "*"` 로 완화 가능하지만 기본값을 바꾸지 말 것.
- `tos_notice` 가 붙으면 robots.txt **주석에 이용 제한 문구**가 있다는 뜻이다. 기계 판정 밖이므로 리드가 원문을 읽고 판단한다 — "파싱 못 했으니 없음"으로 넘기면 하드 게이트의 ToS 축이 조용히 사라진다.
- **로그인 · 페이월 · CAPTCHA 는 이 스크립트로 판정 불가**하다. 취득 시도 중 관측해 같은 형식으로 원장에 적는다.

### P2 — 워커 계약 (은닉의 실체)

워커에게 주는 것: 담당 축 1개 · 질의 · 취득 사다리(`references/acquisition.md`) · 반환 형식.
워커에게 **주지 않는 것**: 등급 점수 · 축 가중치 · 합격 문턱 · 다른 축의 산출.

워커 반환:

```json
{ "frame_id": "f3", "findings": [ { "url": "...", "claim": "...", "verbatim": "...", "accessed_at": "..." } ],
  "self_report": { "S1": {"y": true, "why": "..."}, "S2": {...}, "S3": {...}, "S4": {...}, "S5": {...} } }
```

`grade` 필드는 **워커 산출에 없다.** 등급은 독립 채점자가 부여한다.

**재조사 지시문은 "이 축이 약하다"까지만 쓴다** — 점수·문턱·목표치를 적지 않는다. 문턱을 아는 조사자는 문턱을 향해 최적화한다(원본을 찾는 것보다 원본이라고 주장하는 게 싸다).

### P2.5 — 워커 프롬프트 조립 (은닉의 구현 = 파일 경계)

**조립 입력은 다음 3개뿐이다.** `references/scoring.md` 는 **입력 목록에 없다** — 그 파일을 열지 않는 것이 은닉의 전부이고, 접근 통제나 주의력에 의존하지 않는다.

| 조립 입력 | 무엇 |
|---|---|
| 사용자 질의 + P0 답변 | 조사 대상·마감 |
| `references/frames.md` | 담당 축 1개의 정의 |
| `references/acquisition.md` | 취득 사다리·하드 게이트 |

아래 템플릿을 그대로 채워 쓴다. `{}` 만 치환하고 문장을 늘리지 않는다 — 늘어난 문장이 수치를 실어 나른다.

```text
질의: {질의}
담당 축: {frame_id} — {축 이름}: {frames.md 의 축 정의 1줄}
당신은 이 축만 조사한다. 다른 축은 다른 조사자가 맡고 있고, 그쪽 산출은 보지 않는다.

취득: references/acquisition.md 의 사다리를 위에서부터 시도한다.
  탐색 순서: 최신 발행분부터 연다. 오래된 자료도 근거가 되지만, 더 최신의 정정·후속을 확인하기 전까지
  결론으로 굳히지 않고 확인 여부를 findings 의 claim 에 1줄 적는다.
  robots.txt·ToS·페이월·CAPTCHA 는 우회하지 않는다 — 미도달로 기록한다.
  2차 자료를 근거로 쓸 때는 원본 링크 추적을 1회 시도하고, 실패하면 "원본 미도달"이라 적는다.
  페이지 열기 = acquisition.md 사다리. WebFetch 로 안 열리거나 JS 렌더가 필요하거나 브라우저로만 볼 수 있는 공개 페이지·SNS 일 때만 aside(없으면 다른 브라우저 도구, 그것도 없으면 건너뛰고 한계 기록) · 로그인/페이월/CAPTCHA/robots·ToS 차단은 aside 로도 열지 않음 · 제출 시 acquired_via(webfetch|aside|api|browser|none) 기록.

반환(JSON):
{
  "frame_id": "{frame_id}",
  "findings": [ { "url": "", "claim": "", "verbatim": "", "accessed_at": "" } ],
  "self_report": {
    "S1": {"y": true|false, "why": "근거 1줄"},
    "S2": {"y": true|false, "why": "근거 1줄"},
    "S3": {"y": true|false, "why": "근거 1줄"},
    "S4": {"y": true|false, "why": "근거 1줄"},
    "S5": {"y": true|false, "why": "근거 1줄"}
  }
}

S1 근거강도 / S2 교차검증 / S3 반증탐색 / S4 신선도 / S5 공백선언 — 각 Y/N + 근거 1줄.
findings 에 등급 칸은 없다. 등급은 당신이 매기지 않는다.
원장 파일에 직접 쓰지 않는다 — 산출을 반환하면 병합은 리드가 한다.

마감: {마감 시각}. 도달하면 그 시점 산출을 그대로 반환한다(미완도 반환).
```

**재조사 라운드 추가문** (이것 외의 문장을 붙이지 않는다):

```text
재조사: {축 이름} 이 약하다. {약한 이유를 관측 사실로만 1줄 — 예: "독립 경로가 하나뿐이다" / "반대 증거를 찾지 못했다"}
{한 문장 지시 — 예: "독립 경로를 하나 더 찾아라" / "반대 증거를 찾아라"}
```

조립 후 검사:

```bash
node scripts/hide-check.mjs --session <세션 id> <조립된 프롬프트 파일>...
# 0=PASS · 1=누출 또는 검사기 사망 · 2=스크립트 오류(통과 취급 ❌)
```

> `--session` = 서버 원장의 질문 원문(start.question)을 읽어, 브리프 안에서 **질문 줄을 그대로 옮긴 구간**의 매치만 면제한다(운영자 질문의 주제 숫자 `60%` 등은 리드 전용 층이 아니다). 값 면제가 아니므로 리드가 질문 밖에 적은 기준 문구는 그대로 걸린다. 면제 매치는 `면제(질문 원문)` 으로 찍힌다. 면제 원천은 `--session` 하나뿐이다 — `--question` 은 셀프테스트 전용이라 본 경로에서는 exit 2 로 거부되고, 원장이 없으면 플래그 없이 돌린다.
>
> 면제는 질문 원문 구간만 · 면제 N건이 뜨면 사람이 확인(PASS·누출 줄의 `⚠️ 면제 N건 — 사람 확인` · 원장 위치를 `SEARCHFLOW_STATE_DIR` 로 바꿨으면 그 줄에 함께 찍힌다) · 의도적 우회는 못 막는 자가 점검이다.

> ⚠️ 검사 대상은 **조립 결과물**이다. 이 SKILL.md 나 `scoring.md` 를 대상으로 넘기면 당연히 걸린다 — 그건 리드 전용 층이라 걸리는 것이 정상이다.
>
> exit 1 이 나면 프롬프트를 **수리한 뒤** 스폰한다. 패턴을 좁혀서 통과시키지 않는다(패턴을 좁히면 은닉이 함께 얇아진다).

### P3/P4 — 독립 채점자와 리드 전달

매 라운드마다 조사원·리드와 다른 **새 컨텍스트의 독립 채점 서브에이전트**를 스폰한다. Claude Code는 Agent/Task, Codex는 `spawn_agent`를 쓴다. 이전 라운드 채점 문맥을 승계하거나 조사원을 채점자로 재사용하지 않는다.

- 입력: 질의·유형, 프레임별 워커 산출 파일, `references/scoring.md`. 조사 워커에게 scoring.md를 전달하지 않는 기존 은닉 경계는 유지한다.
- 출력: `out/grades-r<N>.json`. 프레임별 출처의 `grade`, `status`, `stance`(support/refute/neutral), `published`(YYYY/ YYYY-MM/ YYYY-MM-DD 또는 미확인 시 생략), 판단 근거를 기록한다. 하중 수치 최소 3건은 원문을 재확인하고 URL·원문·대조 결과를 함께 기록한다 — 원문 재확인 때 사다리 ③ 조건에 맞는 페이지만 aside 로 열고(없으면 한계 기록) grades 에 acquired_via 기록. 끝까지 못 연 http(s) 페이지(`status=unreachable` 또는 `grade=UNREACHABLE`)는 aside(또는 다른 브라우저 도구)로 시도한 기록(`acquired_via=aside|browser`)이나 건너뛴 이유 `aside_skip`(`hard-gate` = 로그인·페이월·CAPTCHA·robots·ToS · `no-browser-tool` = 브라우저 도구 없음) 중 하나를 반드시 단다 — server-owned 면 둘 다 없는 페이지가 있는 프레임을 `searchflow_gate` 가 한 번 돌려보내고(원장 rule `aside`), 다시 봐도 그대로면 «aside 시도 없이 남았다»를 보고서 한계에 적게 한다(실제 사용 세션의 원장 사례: JS 렌더 상세 페이지·SNS 를 «브라우저·aside 시도 없음»으로 두고 done). 원문 미도달이나 대상 수치 부족은 공백으로 명시하며 대조를 꾸미지 않는다.
- **server-owned**: 서브에이전트는 MCP 도구를 호출하지 못한다. 채점자가 파일 기록 → 리드가 그 파일의 출처 값을 **그대로 `searchflow_submit`** → 리드가 `searchflow_gate`. **리드는 등급을 재해석·수정하지 않는다.** 유효하지 않은 파일은 채점자에게 돌려보낸다.
- **끝 기준 대조**: 채점자는 grades 파일에 `done_check` 도 적는다 — 운영자의 끝 기준(P-1 `evidence.done`)을 «·»·«+»·쉼표 등으로 나눈 부분마다 `{item: 끝 기준에서 따온 부분 글(부분을 통째로 담아야 덮은 것으로 침), met: true|false, evidence_urls: [그 부분을 채우는 used 출처 URL], frame_id(선택)}` 하나, 추이·추세·변화·시계열 등의 부분은 `points: [{date, value, url}]` 로 **날짜가 다른 관측 둘 이상**(한 시점 스냅샷만이면 `met=false`). server-owned 면 리드는 그 `done_check` 를 그대로 `searchflow_gate` 에 넣는다 — 다른 규칙이 다 통과했는데 대조표가 없으면 서버가 `done_check_required`(라운드로 안 셈)를 돌려주고, 안 찬 부분(met=false · used 출처 없음 · 끝 기준에 있는데 목록에 없음 · 추이인데 날짜 다른 관측이 둘 미만)이 있으면 그 프레임을 한 번 돌려보내고(원장 rule `done_criteria` + `unmet` 목록), 다시 봐도 남으면 `done` 이 아니라 `done_with_gaps` 다. 서버가 재는 것은 글자 대조·URL 이 used 출처인지·추이 관측 날짜 수까지 — «정말 그 부분을 채우는가»는 채점자 신고다. skill-owned 면 채점자가 같은 대조를 판정 파일에 적고 리드가 따른다(서버 강제 없음). 근거 = 실제 사용 세션의 원장 사례: 끝 기준 «시작 이후 추이»가 한 시점 스냅샷뿐인데 `done`.
- **skill-owned**: 채점자가 scoring.md에 따라 축 점수·판정까지 파일에 기록하고, 리드는 그 판정을 따른다.
- 원장·보고서 환경·한계에 `grader: independent-subagent`를 기록한다(spawn-plan 라벨 `grader=independent-subagent`). 스폰 불가·거부 환경에서만 사유와 함께 `grader=lead(degraded)`와 `grader_reason=<스폰 불가 사유>`를 명시하고 리드가 채점한다. 조용한 강등은 금지한다.
- 재조사는 최대 3회다. 각 재조사 후 채점자도 새로 스폰한다.

등급 기준 · 축 가중치 · 문턱은 **`references/scoring.md`(🔒 독립 채점자 전용)** 에 있다. 이 파일과 `references/frames.md` · `acquisition.md` · `report-contract.md` 에는 그 수치가 없다 — 워커 프롬프트가 이 경로만 밟도록 조립하기 때문이다(§P2.5).

⚠️ `scoring.md` 의 등급 점수·가중치·문턱은 **전부 잠정값**이다. census held-out 검증 전에는 고정하지 않으며, 실측처럼 인용하지 않는다.

원장 기록은 **single-writer**: `sources.jsonl` append 는 리드 프로세스만 한다. 워커는 자기 산출을 개별 파일로 반환하고 리드가 병합 기록한다(JSONL 동시 append 경쟁을 설계에서 제거).

기록 후 `node scripts/grade-ledger.mjs <경로>` 로 스키마를 검증한다. exit `1`=위반 수리, exit `2`=스크립트 오류이며 **통과 취급하지 않는다**(사유 기록 후 core 진행).

## 3. 하네스 분기 — 조사 단위 스폰

### Claude Code (3단 폴백)

| 순위 | 경로 | 조건 | tier 라벨 |
|---|---|---|---|
| 1 | **`Workflow` 도구** — 축별 워커를 한 스크립트로 팬아웃 | 리드 자기 tool surface 에 `Workflow` 노출 | `cc-workflow` |
| 2 | **서브에이전트**(`Task`/`Agent` — 읽기 전용 조사) 축별 병렬 | 1단 부재, `Task` 또는 `Agent` 노출 | `cc-subagent` |
| 3 | **순차 실행** + 격하 라벨 | 둘 다 부재 | `sequential` |

🔴 **1단 도구 이름을 여기 적어두는 것 자체가 배선이다.** 하네스가 병렬 도구에 *사용자 명시 opt-in* 을 요구하는 경우, 그 조건 중 하나가 **"스킬의 지시가 그 도구를 부르라고 할 때"** 다. 이름을 안 적으면 도구가 있어도 리드가 자제해 2단으로 내려가고, **그 강등은 라벨 없이 일어난다**(성능은 떨어지는데 보고서에는 흔적이 없다). 그래서 1단은 이름으로 지목한다.

**부재 판정은 리드가 자기 tool surface 로 한다.** `env-detect.mjs` 의 값은 참고용이다 — shell 프로세스는 모델의 도구 노출을 대신 판정할 수 없다.

> 실측 참고(2026-07, CLI 2.1.220 · headless): 플러그인·설정·MCP 전부 0인 프로필에서도 `Workflow` 는 기본 도구 목록에 있었고 실호출도 됐다. 즉 3단 폴백의 1단은 통상 실재한다. 반면 CLI 의 **최소 모드(`--bare`)에는 1·2단이 동시에 없었다** — 3단은 이론적 바닥이 아니라 실재 경로다(`fixtures/ac9-degrade-bare.sh`). 버전 의존일 수 있으므로 그 fixture 는 버전 스탬프를 들고 있다.

### Codex CLI (capability adapter)

| 순위 | 경로 | 조건 | 층 |
|---|---|---|---|
| 1 | 공개 `multi_agent` API (spawn / send-or-resume / wait) | tool surface 에 노출 | **core** |
| 2 | `collab_v2` (spawn_agent / send_message / `followup_task` / wait_agent) | v2 namespace 노출 시 | enhanced |
| 3 | 순차 실행 (같은 프레임 목록) + `parallelism=sequential` 라벨 | 어느 multi-agent API 도 없음 | core 폴백 |

**goal**: top-level 1개(조사 전체 대표) + 리드가 task DAG 를 든다. goal 트리(하위 goal) 는 만들지 않는다.
- thread 에 이미 active goal 이 있으면 **새 goal 생성을 시도하지 않고** task DAG 만으로 진행 + `goal=skipped-collision` 라벨.
- run 종료 시 goal 을 **close/complete 로 명시 종결**한다. 방치된 goal 이 다음 run 의 충돌 원인이 된다.

**순차 강등은 프레임을 합치지 않는다.** 특히 `factcheck` 의 지지/반증 축은 순차에서도 별개 조사 단위로 유지한다(편향 차단 장치 — `frames.md` §2).

### 경로 등가 — 기계로 강제한다

tier 는 **실행 방식과 라벨만** 바꾼다. 조사 단위 집합은 어느 tier 에서도 같아야 한다. 눈으로 지키지 않고 스크립트로 고정한다:

```bash
node scripts/spawn-plan.mjs --type <유형[,유형2]> --harness cc --tools "<리드가 실제로 보는 도구 이름들>"
node scripts/spawn-plan.mjs --type <유형>          --harness codex --multi-agent-api public|collab_v2|none
# stdout: {"harness":…,"tier":…,"parallelism":…,"units":[{frame_id,type,axis}…],"labels":[…],"dedupe_required":bool}
# exit 0=계획 · 1=입력 계약 위반 · 2=스크립트 오류(통과 취급 ❌)
node scripts/spawn-plan.mjs --test   # 경로 등가·순차 분리 유지·상한·폴백·음성 대조
```

- 유형→축 표의 **유일 SoT 는 `references/frames.md` §2** 다. 스크립트는 그것을 파싱한다 — 표를 코드에 복제하지 않는다(이중 관리는 한쪽만 갱신되는 순간 조용히 갈린다).
- `dedupe_required:true` = 복합 유형이다. **의미적 중복 접기는 기계가 못 한다** → 리드가 `frames.md` §1 결합규칙 2 를 적용하고, 접은 축을 「관찰 범위 선언」에 적는다.
- `labels` 를 보고서 「환경·한계」 칸에 **그 문자열 그대로** 옮긴다. 문자열이 바뀌면 격하 여부를 기계로 확인할 수 없게 된다.

## 4. 질문 주체 = 리드 일괄

**스폰 전에 리드가 유형별 템플릿으로 1회 묶음 질문**을 한다. 축마다 따로 묻지 않는다 — 병렬 조사자들이 각자 사용자에게 물으면 사용자가 동시에 여러 질문을 받고 전원이 답까지 블록된다.

묶음 질문에 **반드시 포함**: 마감 시한(1차 종료 조건).

채널 = 아래 「운영자 질문 창구」 사다리. P-1 질문과 P0 묶음 질문이 같은 사다리를 쓴다 — «질문 못 함 → 바로 기본값»으로 건너뛰지 않는다.

### 운영자 질문 창구 (사다리)

1. **운영자가 같은 대화 화면에 있으면** = 대화형 질문 도구(Codex = 리드가 사용자에게 직접 묻고 답을 워커에 주입).
2. **아니면 = 하네스 규칙이 정한 운영자 메시지 창구**(DM 등)로 질문을 보낸다 → `searchflow_await_operator` 로 기록 → 그 턴을 끝낸다 → 답이 도착하면 `searchflow_pending` 으로 이어 갈 인터뷰를 찾아 재개한다(압축·재시작 뒤에도). 대기 시간 상한 없음. 창구는 하네스가 정한다 — 질문이 나가고 답이 들어오는 목적지라, 프로젝트 폴더의 설정 파일이 바꿀 수 있는 값(환경변수 등)으로 받지 않는다. 답은 그 창구에서 운영자가 보낸 것만 쓴다.
3. **1·2 모두 없을 때** = P-1 미달 질문은 **조사 ❌ 유지**(기본값으로 넘어갈 수 없다). 마감 시한 기본값(§ 비대화 실행)은 봇 자체 조사(`origin = bot`)나 자동 모드에서만 쓸 수 있고, 이때 보고서 `deadline=default` 표기는 **필수**. 사람이 시킨 조사는 원래 말에 시한(§0.5 받는 꼴)을 넣거나 인터뷰의 자동 모드 칸에 «예»라고 답해야 시작된다(원래 말의 «자동 모드로 해 줘»는 근거가 아니다).

`searchflow_start` 의 `deadline_source` = 시한을 운영자에게 받았으면 `operator`, 기본값이면 `default`(생략하면 default) — 원장 `start` 이벤트에 남는다. 사람이 시킨 조사에서 `default` 는 자동 모드가 아니면 거부된다(§0.5).

### 스폰 후 새 질문 (blocked node)

워커가 조사 중 새 질문을 발신하면:

1. 리드가 **중복 제거**
2. **라운드 경계에서 묶음 질문 최대 1회/라운드**
3. 답 대기 중 **다른 프레임은 독립 진행**
4. 답 수신 시 §3 경로로 주입해 재개

**relay envelope**: `{run_id, frame_id, question_id, round, status}` — `status` 전이 = `pending → asked → answered → resumed`, 각 전이는 리드만 기록. 기록 위치 = `out/relay.jsonl`(리드 single-writer, 원장과 같은 규율).

```bash
node scripts/relay-check.mjs out/relay.jsonl
# stdout: {run_id,records,questions,frames,efup:[…],in_flight:[…],violations:[…]}
# exit 0=위반 0 · 1=위반(빈 원장 포함 — 0건은 통과가 아니다) · 2=스크립트 오류
node scripts/relay-check.mjs --test   # 양성 + 음성 5종 + exit 계약
```

**완료 워커 재진입(E-FUP)**: 어떤 축의 라운드 1 주기가 `resumed` 까지 끝난 뒤 그 축에 라운드 2 질문이 열리면, 리드는 그 워커를 **재스폰하지 않고 재진입**시킨다(`collab_v2` 는 `followup_task`). 재스폰하면 라운드 1에서 이미 읽은 것을 다시 읽는다. `relay-check` 의 `efup` 배열이 원장에 그 형태가 남았는지 확인한다.
⚠️ 그 검사는 **원장의 형태**를 재는 것이고 런타임이 실제로 재진입했는지를 재는 것이 아니다 — GREEN 을 "재진입이 동작한다"로 인용하지 않는다.

### 비대화 실행 (질문 채널 없음)

창구 사다리 1·2 가 모두 없을 때만(예: 운영자 메시지 창구도 지정되지 않은 `codex exec`) **기본값을 채택**한다: 시한 = 시작 + 30분 · 라운드 상한 4. 보고서 「환경·한계」에 `deadline=default` 라벨 **필수**. P-1 미달 질문은 이 경로로도 조사를 시작하지 않는다. 사람이 시킨 조사의 시한 기본값은 자동 모드(인터뷰 자동 모드 칸 «예»)에서만 받는다 — 비대화로 돌릴 사람은 원래 말에 시한(§0.5 의 받는 꼴 — «오늘 18시까지»·«3일 안에»·«11/10» 등)을 적는다. 원래 말에 «자동 모드로 해 줘»를 써도 자동 모드는 켜지지 않는다(0.55.13 — 인터뷰 창구가 없으면 시한을 적는 길뿐).

## 5. preflight (시작 시 1회)

### 5.1 요소 점검·자동 설치(2026-09-03 신설)

```bash
bash scripts/preflight.sh --json   # stdout JSON 1줄 · exit 0 고정(번들 파일 결손만 1)
```

| 라벨 | 뜻 |
|---|---|
| `node=path` · `node=portable` · `node=portable-cached` · `node=brew` · `node=apt` · `node=winget` | node 실행기를 어디서 확보했나 |
| `degraded=no-node-runtime` · `degraded=bundle-incomplete` | `no-node-runtime` = node 확보 실패 — 막지 않고 격하로 완주 · `bundle-incomplete` = 번들 파일 결손 — 진행하지 않고 exit 1 |
| `selftest=pass` · `selftest=skip` · `selftest=fail` | 확보한 node 로 돌린 번들 자체시험 |
| `state=home` · `state=tmp` | 상태 폴더를 홈에 잡았나 tmp 로 강등했나 |
| `mcp=present` · `mcp=registered-restart-needed` · `mcp=skipped-no-install` · `mcp=skipped-no-host` · `mcp=register-failed` · `mcp=unknown-host-timeout` | searchflow MCP 서버 등록 상태 — `skipped-no-install` = 호스트는 있는데 `--no-install` 이라 «시도하지 않음» — 시도했다가 실패한 것은 `register-failed` · `unknown-host-timeout` = 호스트가 시한 안에 답하지 않아 등록을 «시도하지 않음»(부재로 단정하지 않는다) |
| `enhanced=codex:…` · `enhanced=ooo:…` | 강화 요소 — `present`·`installed`·`absent`·`failed` 4값 |
| `enhanced=hook:…` | 지식 조회 훅 — 탐지만 한다: `present`·`absent` 2값 |

**이후 모든 `node scripts/…` 호출은 JSON 의 `node` 경로로 한다** — preflight 가 내려받은 실행기는 PATH 에 없다.

`--no-install`(=`SEARCHFLOW_PREFLIGHT_INSTALL=0`) 은 점검만 하고, `SEARCHFLOW_PREFLIGHT_ENHANCED=0` 은 강화 요소 설치를 생략하며, `SEARCHFLOW_NODE` 는 실행기를 수동 지정한다. codex 등록 대상은 `~/.codex/config.toml` 이고, `CODEX_HOME` 이 설정돼 있으면 그 아래 `config.toml` 이다.

상태 폴더를 tmp 로 강등할 때 이름은 preflight 가 `searchflow`, MCP 서버가 `searchflow-sessions` 로 다르다 — 무해하다(같은 `TMPDIR` 아래 형제 디렉터리).

### 5.2 권한

| 거부된 권한 | 처분 |
|---|---|
| `web` | **hard stop** — 리서치 불능. 사유 보고 후 종료 |
| `shell` | degrade — 스크립트 검증 skip + 라벨 |
| `agent` · `goal` | 순차 강등 |

**거부(permission)와 부재(dependency)를 라벨에서 구분한다.** "도구가 없다"와 "도구를 못 쓰게 했다"는 다른 사실이다. 산문으로만 구분하지 말고 **기계 라벨에서 갈라라** — 순차 강등 시 사유를 골라 넣는다:

| 사유 | 호출 | 라벨 |
|---|---|---|
| **부재** — 이 환경에 오케스트레이션 도구가 없다 | `spawn-plan.mjs --type <t>` (도구 목록에 없음) | `degraded=no-orchestration-tool` |
| **거부** — 도구는 실재하나 정책·권한이 호출을 막는다 | `spawn-plan.mjs --type <t> --tools Workflow,Task --denied` | `degraded=orchestration-denied` |

`--tools` 에는 **실제 보이는 도구를 사실대로** 적고 거부는 `--denied` 로 선언한다. 도구를 목록에서 빼서 순차로 내려가면 라벨이 "없다"고 **거짓 주장**한다. 반대 세탁도 막혀 있다 — 도구 없이 `--denied` 는 exit 1 이다.

> 이 갈림은 실측에서 나왔다(2026-07-31 관측): 세션에 `Workflow`·`Agent` 가 실재했는데 정책이 호출을 금지해 순차로 갔고, 그때 기계 라벨은 부재를 주장했다. 리드가 본문에 사유를 따로 적어 살렸지만 **기계 대조로는 잡히지 않는 거짓말**이었다.

## 6. 에러 매트릭스

| 상태 | 처분 |
|---|---|
| `success` | 정상 종료 |
| `deadline` | 시한 도달 — **현재 산출을 조건부 반환**(점수 · 미충족 축 · 사유 명시) |
| `cancel` | 사용자 중단 — 원장·부분 산출 보존 |
| `agent-denied` | 해당 프레임 순차 강등. 전 프레임 거부면 전체 순차 |
| `goal-collision` | goal 없이 task DAG 진행 + 라벨 |
| `worker-error` | 그 프레임 순차 재시도 1회 → 실패 시 **프레임 결측 라벨**로 계속 |
| `malformed-relay` | envelope 키 결손·파싱 불가 = 그 질문 폐기 + 라벨, 워커는 기본값으로 진행 |
| `no-node-runtime` | 스크립트 검증 전부 skip + 독립 채점자 수동 채점(스폰 불가 시 grader=lead(degraded)) 명시 + 라벨 |

## 7. 종료 조건

1. **1차 = 사용자 마감 시한** (P0 에서 물은 값, 비대화면 기본 30분)
2. **2차 = 라운드 상한 4회**

시한 도달 = 실패가 아니다. **현재 산출을 조건부로 반환**하고 「종료 조건 성적표」 칸에 어디서 멈췄는지 적는다. 미달인 채로 정직하게 보고하는 것이 무한 재조사보다 싸고 정직하다.

## 8. 산출

- `out/report.md` — `references/report-contract.md` 의 칸 목록 전건. 합성 배열은 `references/synthesis.md`
  (유형별 템플릿·판정표 스켈레톤). **템플릿이 조사를 늘리지 않는다** — 빈 칸은 「공백 선언」으로.

```bash
node scripts/report-check.mjs out/report.md --labels "$(node scripts/spawn-plan.mjs --type <유형> --harness cc --tools "<도구>" | node -e 'let d="";process.stdin.on("data",c=>d+=c).on("end",()=>console.log(JSON.parse(d).labels.join(",")))')"
# 칸 목록 SoT = report-contract.md §1 파싱(복제 ❌) · 라벨은 spawn-plan 이 낸 문자열 그대로
# exit 0=위반 0 · 1=칸 부재/제목만/라벨 부재 · 2=스크립트 오류
node scripts/report-check.mjs --test   # 양성 0 / 음성 3종 대조
```

preflight 의 `labels` 를 spawn-plan labels 뒤에 콤마로 잇는다 — 두 집합이 한 문자열로 `--labels` 에 들어간다.

> 이 검사기는 **칸이 있고 비어있지 않은가**만 본다. 내용의 진위·인용 일치·점수 계산은 보지 않는다 — GREEN 을 "보고서가 옳다"로 인용하지 말 것.
- `out/sources.jsonl` — schema v1 (리드 single-writer, `grade-ledger.mjs` 통과)
- `out/relay.jsonl` — 사용자 질문 릴레이 원장 (리드 single-writer, `relay-check.mjs` 통과). 질문이 0건이었으면 이 파일은 만들지 않는다 — **빈 파일을 남기지 않는다**(검사기가 빈 원장을 위반으로 잡는다).

**운영자에게 답할 때** 첫머리 또는 끝에 1줄: `검색 라운드 <n> · 재조사 <n>회 · 판정 <done|done_with_gaps|…>` — 보고서 「환경·한계」의 `operator_questions=<n>` · `deadline_source=…` 와 함께, 운영자에게 몇 번 물었고 시한이 어디서 왔는지 보이게 한다.
