# 취득 사다리 + 차단 존중 하드 게이트

## 1. 사다리 — 위에서부터, 걸리는 곳에서 멈춘다

**같은 단 안에서는 최신 발행분부터 연다.** 최신 자료에서 출발해 원본으로 거슬러 올라가는 것이 정방향이다 —
반대로 가면 그 뒤에 나온 정정·후속을 놓친다. 오래된 자료도 근거가 된다 — 오래됨은 등급과 다른 축이다(→ §3).
다만 더 최신의 정정·후속을 확인하기 전까지 결론으로 굳히지 않고, 확인 여부를 findings 의 claim 또는 S4 why 에 1줄 적는다.

```
① 공식 API · RSS · 공개 데이터셋        ← 가장 싸고 안정적. 먼저 본다
② 일반 HTTP 취득 (WebFetch 등)
③ aside CLI(실행 이름 `aside` · WSL 은 `aside.exe`) ← 아래 3조건일 때 반드시 연다
④ 미도달                                 ← 라벨로 기록하고 넘어간다
```

③ 을 여는 3조건: WebFetch 실패 · JS 렌더 필요 · §3 원본 도달 의무 재확인(핵심 출처는 정적 페이지여도). 명령 꼴: `aside exec "<URL> 페이지를 열고 본문을 요약 없이 그대로 돌려줘"`. aside 가 없으면 playwright 등 다른 브라우저 도구로, 그것도 없으면 이 단을 건너뛰고 보고서 한계에 «③ 미수행» 기록.

③ 도 §2 하드 게이트를 넘지 않는다 — robots.txt·ToS 금지·로그인/페이월·CAPTCHA·봇 감지 페이지는 aside 로도 열지 않고 UNREACHABLE 로 기록.

## 2. 하드 게이트 — 우회 대상이 아니라 기록 대상

다음은 **어떤 단에서도 우회하지 않는다**:

- `robots.txt` 가 막은 경로
- 명시적 ToS 금지
- 로그인 / 페이월 뒤
- CAPTCHA · 봇 감지

막힌 것은 원장에 `grade=UNREACHABLE` · `status=unreachable` 로 남기고, `grade_basis` 에 **무엇이 막았는지** 1줄 적는다. 그리고 그 사실 자체를 보고서 한계에 쓴다.

> **왜 게이트인가**: 이건 예의가 아니라 요건이다. 공개 배포물이 사용자 환경에서 차단을 우회하면 그 책임은 사용자에게 간다. "우회하면 얻을 수 있었다"는 정보는 **없는 정보로 취급**한다.

## 3. 원본 도달 의무

`B`·`C` 등급 소스를 근거로 쓸 때는 **원본 링크 추적을 1회 시도**한다.

- 도달하면 그 소스의 등급이 올라간다 → 점수를 올리는 가장 싼 방법이 **원본을 여는 것**이 되게 설계돼 있다.
- 실패하면 `grade_basis` 에 "원본 미도달" 을 명시한다. 시도하지 않은 것과 시도했으나 못 간 것을 구분한다.
- 원본 재확인은 aside(③)로 연다 · 기록 = 제출 항목 acquired_via=aside.
- 채점자를 건너뛰는 환경(grader=lead(degraded))에서도 리드가 핵심 출처 1건 이상을 aside 로 재확인한다(SKILL P3/P4 «aside 하한»).

## 4. 교차검증에서 세는 단위

**같은 원본을 재보도한 기사 여러 건은 1로 센다.** 독립 경로란 서로 다른 원본에 닿은 경로를 말한다. 재보도 다수를 교차검증으로 세면 하나의 오류가 여러 번 확인된 것처럼 보인다 — 원장에서 `status=discarded` + `discard_reason` 에 "재보도 — 독립 경로 아님" 으로 남긴다.

## 5. 사용불가도 지운다는 뜻이 아니다

`grade=UNREACHABLE` · `status=discarded` 인 소스도 **원장에서 삭제하지 않는다.** 무엇을 왜 버렸는지가 방법론 투명성이고, 보고서의 「사용불가 원장 공개」 칸이 그것을 드러낸다. 버린 기록이 없는 보고서는 "처음부터 그것만 봤다"와 구별되지 않는다.
